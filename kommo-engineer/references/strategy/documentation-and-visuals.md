# Documentation and visual deliverables

Use this module only when a diagram, architecture brief, decision record, operating guide, or approval artifact helps the user act on the work.

- Write for the user's next decision. Put scope, finding, and recommendation before background detail.
- Keep one source of truth for each metric, field definition, threshold, and operating rule; link to it instead of maintaining duplicate values.
- Use a compact Mermaid flow for a static workflow when it improves comprehension. Label approval points, state changes, and system boundaries.
- For a polished Markdown visual, use the installed `documd-visuals` skill when it is available and relevant. For ordinary reference documentation, use `markdown-docs` when appropriate. Neither is a dependency for routine analysis.
- Do not copy or redistribute those skill files into this repository. Follow their installed instructions and source license if using them.
- Date source-sensitive claims, screenshots, benchmark comparisons, and mutable system observations. Keep CRM/customer data out of a reusable example.
